## ✅ Выполненные задачи

### 1. ⚡ Портфолио: изменено количество работ с 6 на 4 (КРИТИЧНО)

**Проблема:** На странице портфолио (без фильтра) в каждом альбоме показывалось по 6 работ (сетка 2×3), что делало страницу слишком длинной.

**Решение:**

  - Desktop: `grid-template-rows: repeat(2, 250px)`
  - Mobile: `grid-template-rows: repeat(2, 200px)`

**Файлы:**
- `apps/portfolio/views.py` (строка 77)
- `static/css/style.css` (строки 628-632, 742-750)

### 2. 🔗 Портфолио: исправлена пагинация — листание работ в модалке (КРИТИЧНО)

- Пагинация по параметру `service` уже корректно работала в шаблоне (строка 188)

**Файлы:**
- `apps/portfolio/views.py` (строка 19)

**Теперь:**
- При клике на фильтр (например, "Вывески") все работы этой категории загружаются на одну страницу
- Модалка листает все работы без ограничений
- Пагинация сохраняет параметр `service` при переключении страниц

### 3. 📝 Админка: добавлено описание кнопки "Восстановить удалённое"

**Проблема:** Непонятно, как работает кнопка "Отменить последнее действие" — что восстановится, как далеко откат, удалится ли загруженное после.

**Решение:**
- Добавлен tooltip и текстовое пояснение:
  - **Tooltip:** "Откатывает к состоянию ДО последнего сохранения (применяет предпоследнюю ревизию). Отменённое действие удаляется из истории. Работает только для ваших изменений."
  - **Видимый текст:** "ℹ️ Откат к предпоследней ревизии (до последнего сохранения)"

**Файлы:**
- `templates/admin/index.html` (строки 14-20)

**Как работает:**
- Откатывается к **предпоследней** ревизии (состояние до последнего сохранения)
- Отменённая ревизия **удаляется** из истории

- Если отмените дважды: `55+ → 80+ → 13+` (каждый раз удаляется последняя ревизия)

### 5. 🐛 Баг загрузки фото: увеличены лимиты, добавлена валидация

**Проблема:** "Периодически при добавлении фото после нажатия кнопки сохранить всё просто исчезает, а не сохраняется фото"

**Причина:**
- Лимит 10 MB был недостаточен для фото с современных телефонов (часто 15-20 MB)
- Не было валидации формата и размера
- Не было сообщений об ошибках

**Решение:**

**А) Увеличены лимиты загрузки:**
- `DATA_UPLOAD_MAX_MEMORY_SIZE`: 10 MB → 25 MB
- `FILE_UPLOAD_MAX_MEMORY_SIZE`: 10 MB → 25 MB

**Б) Добавлены валидаторы в модель:**
- `validate_image_size` — проверка размера (максимум 25 MB)
- `validate_image_extension` — проверка формата (jpg, jpeg, png, webp)
- При ошибке выводится понятное сообщение с текущим размером файла

**В) Улучшена админка:**
- Добавлено описание в fieldset: "⚠️ Требования к изображению: максимум 25 MB, форматы jpg/png/webp. Рекомендуемый размер: 800x600px."
- Добавлен метод `save_model` с сообщениями об успехе/ошибке

**Файлы:**
- `config/settings.py` (строки 126-127)
- `apps/portfolio/models/portfolio.py` (новые функции `validate_image_size`, `validate_image_extension`)
- `apps/portfolio/admin.py` (обновлён fieldset, добавлен `save_model`)

**Теперь:**
- Фото до 25 MB загружаются без проблем
- При превышении лимита — понятное сообщение с размером файла
- При неверном формате — список допустимых форматов

## ⚠️ Важные замечания

1. **Пагинация портфолио:** если в одной категории будет > 100 работ, пагинация включится автоматически. Если нужно показывать все работы всегда, измените `paginate_by = None` в `PortfolioListView`.

2. **Валидаторы изображений:** работают на уровне Python (при сохранении формы). Если загружать файлы напрямую через API/консоль, валидация не сработает.

3. **Лимиты Nginx/веб-сервера:** если используете Nginx, убедитесь, что `client_max_body_size` >= 25 MB в конфигурации Nginx:
   ```nginx
   client_max_body_size 25M;
   ```

4. **Кнопка "Отменить":** работает только для **ваших** изменений (user-specific). Нельзя отменить действия других администраторов.
